# ADR 0008: 専用のデータカタログは使わず、Glue と dbt docs で代用する

- 日付: 2026-11-03
- 状態: 採用(規模が大きくなったら見直す)

## 状況

データを「探す」「意味を知る」ための仕組みが要るかを決める。専用のツールには、OpenMetadata や DataHub などがある。

## 決めたこと

- 専用のデータカタログは入れない。
- テーブルの定義は、**Glue Data Catalog** が持つ(Athena と Iceberg が使う、技術的なカタログ)。
- 人が探すためのカタログは、**dbt docs** で代用する。dbt の meta / tags にオーナー、PII フラグ、更新頻度を持たせ、用語集も用意する(フェーズ3)。dbt docs は公開する。

## 理由

- テーブルは約 9 つで、使う人は1人である。専用ツールは、サーバーを動かして保つ手間のほうが大きい。
- dbt docs は、モデルの説明、列、テスト、依存関係を自動で出せる。dbt を使うので、追加の仕組みがいらない。
- 月額の上限(10 ドル)に合う。

## あきらめたこと(弱い点)

- ツールをまたいだ検索や、データの出どころの追跡(リネージ)は持てない。OpenLineage も対象外にしている。
- 次のどれかになったら、専用のツールを選択肢に入れる。
  - テーブルや使う人が増え、dbt docs では探しにくくなる。
  - dbt の外で作られるデータ(他のツールの出力)も、まとめて管理したくなる。
