# ADR 0006: S3 は環境ごとに1バケットにし、プレフィックスで用途を分ける

- 日付: 2026-11-03
- 状態: 採用(dev のみ実装済み)

## 状況

データレイクの置き場所を決める。環境は dev / test / prod の3つで、AWS アカウントは1つである(ADR 0001)。

## 決めたこと

- バケットは、環境ごとに1つ。名前は `ecom-lakehouse-<環境>-<アカウント ID>`。
- 中をプレフィックスで分ける。

| プレフィックス | 用途 | 消し方 |
|---|---|---|
| `raw/` | 取り込んだ Parquet(Bronze の外部テーブルが読む) | 消さない |
| `iceberg/` | Silver、Gold(Iceberg) | Iceberg の expire / vacuum に任せる。期限のルールは掛けない |
| `athena-results/` | Athena のクエリ結果 | 7日で削除 |
| `logs/` | 取り込みのログ(ADR 0005) | 90日で削除 |
| `quarantine/` | 隔離した行(ADR 0005) | 30日で削除 |

- バケットの設定: パブリックアクセスのブロック、暗号化、TLS のみを許すポリシー。
- 権限はロールで分ける。`ecom-<環境>-ingest` は `raw/` の読み書きだけで、`logs/` と `quarantine/` は書き込みだけ。`iceberg/` には入れない(2026-11-01 に AccessDenied で確認)。

## 理由

- 1つのバケットなら、名前の管理とポリシーが単純である。
- 用途ごとに削除の期限が違うので、プレフィックスごとにライフサイクルを掛けられる。
- `iceberg/` に期限のルールを掛けると、Iceberg の台帳(メタデータ)とデータの整合が崩れる。Iceberg のデータは、Iceberg の機能で消す。

## あきらめたこと(弱い点)

- 層ごと、または用途ごとにバケットを分けると、バケット単位で強い境界を引けるが、今回はしなかった。境界は、ロールの権限とプレフィックスで引いている。
- 環境の分離は名前だけである(ADR 0001)。アカウントを分けたときは、バケットの名前を見直す。
