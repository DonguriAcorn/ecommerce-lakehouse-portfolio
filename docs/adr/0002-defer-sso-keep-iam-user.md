# ADR 0002: 管理者は IAM ユーザーのままにし、SSO は後回しにする

- 日付: 2026-11-03
- 状態: 採用(見直しの条件は、下の「あきらめたこと」に書く)

## 状況

人が AWS を操作する入口が要る。いま使っているのは、IAM ユーザー `portfolio-admin` の長期のアクセスキー(手元の `~/.aws`)である。実務では、IAM Identity Center(SSO)で一時的な鍵を使う。

## 決めたこと

- 人の入口は、IAM ユーザー `portfolio-admin` のままにする。SSO は後回しにする。
- 鍵を持たない形は、**人以外の入口**で第一に選ぶ。
  - AWS の中の処理は、`portfolio-admin` からロールを借りる(AssumeRole)。
  - GitHub Actions から AWS へは、OIDC で一時的な鍵を受け取る(OIDC プロバイダはアカウント共通の `terraform/global` に作成済み。ロールはフェーズ4)。
- 長期の鍵を守るために、次を行う。
  - ルートユーザーと `portfolio-admin` に MFA を付ける。
  - 鍵は 90 日を目安に交換する。
  - 鍵をリポジトリと Docker のイメージに入れない。
  - 鍵が要る他のものは、SSM Parameter Store の SecureString に置く(`/ecom/<環境>/<用途>`)。

## 理由

- 個人の学習用で、AWS アカウントが1つである。
- 学習の中心はデータ基盤で、人の認証基盤の導入と運用に時間を割かない。
- 長期の鍵が残る場所は、手元の `~/.aws` の1か所だけにできる。人以外の入口は、鍵を持たない形で作れる。

## あきらめたこと(弱い点と、見直しの条件)

- 鍵が漏れると、期限がないので、無効にするまで使われる。そのため、漏れたときの手順(鍵の無効化を最初に行う)と、gitleaks などの守りの層を secrets.md に置いた。
- 次のどれかになったら、SSO に移す。
  - 複数の人が AWS を使う。
  - 環境ごとにアカウントを分ける(ADR 0001 の見直し)。
  - 会社の環境に展開する。
