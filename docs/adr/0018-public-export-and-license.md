# ADR 0018: 公開用の Parquet export と、Olist のライセンスの扱い

- 日付: 2026-11-28
- 状態: 採用
- 関係: handoff §4(公開アプリに AWS の認証情報を持たせない)、[ADR 0015](0015-gold-grain-and-scd2.md)(Gold の粒度)、tasks.md のフェーズ5

## 状況

フェーズ5で、Streamlit のダッシュボードを公開する。公開アプリに AWS の認証情報は持たせない。そこで、Gold から公開用の小さな集計を Parquet に書き出し、アプリは DuckDB でそれを読むだけにする。あわせて、元データ Olist のライセンス(Kaggle の表記は CC BY-NC-SA 4.0)を、公開の範囲に反映する必要がある。

## 決めたこと

### ライセンス

1. Kaggle のデータセットページの License 欄は CC BY-NC-SA 4.0(2026-11-28 にユーザーが目視で確認)。条件は、出典の表記、非商用、同じライセンスでの公開。
2. 公開するのは集計済みの Gold だけにする。注文や明細の行単位のデータは、GitHub にもアプリにも出さない。
3. 出典の文言を、README とアプリのフッターに書く。派生物(集計)は CC BY-NC-SA 4.0 で公開する、とも書く。このポートフォリオは非商用の学習用であることも書く。

### export

4. 置き場所は、GitHub のリポジトリ内(`app/data/`)にする。Streamlit Community Cloud はコードと一緒にそれを読む。S3 は公開しない。理由は、無料であること、公開アプリに AWS の鍵が要らないこと、公開のバケットを作らずに済むことの3つ。
5. 出す表は、粗い粒度の3つ。列は、ダッシュボードの4画面(gold-design.md §1)に要るものだけにする。
   - `kpi_monthly`(月 × 州): GMV、注文数、平均注文額。期間比較(前月比、前年同月比)は、アプリ側でこの表から計算する。
   - `repeat_monthly`(月 × 州): 注文のある本人の数と、2注文以上の本人の数。分母に `is_counted` を使うかは、画面を作るときに決める(tasks.md の未決)。
   - `category_monthly`(月 × カテゴリ): GMV、販売数、平均の星の数。商品ランキングは、v1.0 ではカテゴリ単位にする。商品単位(`product_id`)は出さない。
6. 出さないもの: `customer_unique_id`(ハッシュも含む)、`customer_sk`、`order_id`、郵便番号、日単位の集計、商品単位の集計。
7. 健康状態ページ用に、export のときに `status.json`(export の時刻、各表の行数、最新の注文日)を1つ出す。
8. 5の3表は、dbt の Gold モデル(`pub_kpi_monthly`、`pub_repeat_monthly`、`pub_category_monthly`)として作る。集計の定義を dbt に1か所にまとめ、YAML の説明・tests・`contract: enforced` を付けるため。置き場所は既存の Gold と同じスキーマ(`ecom_<環境>_gold`)で、接頭辞 `pub_` で公開用と見分ける(別のスキーマに分けるほどの規模ではないため)。元の Gold の5モデルは変えない。
9. export は、dbt の後に流す Python のスクリプトにする。3つの `pub_` 表を Athena で読み、Parquet に書くだけで、SQL は持たない。実装は別のタスク。

## 理由

- 集計だけなら、元の注文を特定されにくく、ライセンスの「再配布」の範囲も最小になる。
- GitHub 置きなら、費用と設定が増えない。更新はコミットになるが、小さい表なので、サイズは数 MB 以下の見込み。
- 粗い粒度(月 × 州、月 × カテゴリ)にすると、件数が少ない行から、元の注文を推測されにくくなる。

## あきらめたこと(弱い点)

- 商品単位のランキングと、日単位の細かい推移は、公開アプリでは見られない(必要なら、粒度を見直して ADR を足す)。
- 月 × 州には、注文が数件しかない組み合わせがある。件数の少ない行を隠す処理(小さいセルの抑制)は、v1.0 では入れない。実装のときに、行数の分布を見て再検討する。
- データを更新するたびに、`app/data/` の Parquet がコミットになる。
- 同じライセンス(SA)での公開が条件なので、アプリのデータは、あとで商用に切り替えられない。
