# ADR 0019: 検証・隔離・型付けは Bronze の前(取り込み)で行う

- 日付: 2026-11-28
- 状態: 採用。型を付ける場所と Raw の置き方は [ADR 0004](0004-raw-snapshot-typed-parquet.md)、検証と隔離の中身は [error-handling.md](../design/error-handling.md)。この ADR は 0004 を置き換えず、層ごとの役割を補う
- 関係: [ADR 0003](0003-table-definition-management.md)(Bronze は外部テーブル)、[ADR 0010](0010-raw-event-records.md)(Raw は出来事の記録)、[ADR 0011](0011-replay-tables-from-bi.md)(7表の共通の受付)

## 状況

メダリオンの一般形では、Bronze が届いたものを全部そのまま受け取り、検証と型付けは Silver で行う。変な値も Bronze に残るので、あとから SQL で調べたり、ルールを変えて Silver を作り直したりできる。

このプロジェクトは、Python の取り込み(`ingestion/`)で検証と型付けをしてから Raw に書く。Bronze は Raw を読む外部テーブルなので、Bronze に入るのはもう検証を通った行だけになる。2026-11-28 のメダリオンの確認で、この違いを記録していないこと、弾いた行が手元の `data/quarantine/` にしか残っていないことが分かった。

前提は次の3つである。

- 送る側(業務システムの代わりの `simulator/`)との約束(列、型、期間)は、registry(`ingestion/schema.py`)の1か所に書いてある。
- 届いたファイル(`data/source/`)は手元に残るので、Raw はいつでも作り直せる。
- 取り込みは毎日 Airflow が動かし、失敗すると dbt は流れない。

## 決めたこと

- **取り込みで、Raw に書く前に次の3つを行う。**
  1. 約束の検証。ファイルがない、読めない、必要な列がない場合は、その日の実行を止める。
  2. 悪い行の隔離。空のキー、日時として読めない値、知らない種類などの行だけを quarantine に移し、残りの行は通す。隔離した行が 1% を超えたら、元データの大きな異常とみなして止める。
  3. 型付けと監査カラム(`_ingested_at`、`_source_file`、`_batch_id`)。詳しくは ADR 0004。
- **隔離した行は S3 にも残す。** その日の隔離ファイルを、`upload_logs`(Airflow のタスク)が取り込みログと一緒に `quarantine/` に上げ、30 日で消す(バケットのライフサイクルのルール)。取り込みが失敗した日も上げる。
- **層の役割**
  - Raw / Bronze: 検証を通った行を、届いた日ごとに積むだけ。Bronze は Terraform の外部テーブル。
  - Silver: 積んだ行を「いまの状態」に畳むだけ(MERGE)。日をまたぐ重複など、1日のファイルでは分からない点は dbt test で見る。
  - Gold: 結合と集計。

## 理由

- **悪いデータが下流に広がらない。** 型の合わない行が Bronze に入ると、Silver、Gold、公開用の集計まで、すべての層で同じ例外の処理が要る。入口で止めれば、後ろの SQL は「正しい形で届く」と前提にできる。
- **Silver の SQL が単純になる。** Silver は畳むことに集中でき、検証の分岐を持たない。日次の MERGE と冪等性の確認(ADR 0014)が読みやすくなる。
- **検証を Python で書き、pytest で確かめられる。** 隔離の条件を1つずつ単体テストにでき、7表で共通の受付(ADR 0011)を使い回せる。
- **元のファイルが残る。** `data/source/` から Raw を作り直せるので、一般形の「Bronze に生のまま残す」安全網の役は、届いたファイルが担う。

## あきらめたこと(弱い点)

- **Raw が届いたままの姿ではない。** 検証のルールを変えたら、SQL だけでは直せず、`data/source/` から取り込み直す必要がある(ADR 0014 のバックフィルで流す)。
- **弾いた行は SQL から見えない。** `quarantine/` には外部テーブルを作っていないので、Athena で隔離の傾向を集計できない。調べるときは、Parquet を手元で読む。要るようになったら、Bronze と同じ形で外部テーブルを足す。
- **変な値の傾向を貯められない。** 一般形なら、少し変な値も Bronze に入り、あとで分析できる。ここでは隔離して 30 日で消し、1% を超えたら取り込みを止める。
- **本番では、元のファイルが残るとは限らない。** 送る側がファイルを消す、または API で一度しか取れない場合は、作り直しの元がなくなる。その場合は一般形に寄せ、届いたものをそのまま Bronze(または S3 の別のプレフィックス)に保存してから、検証を Silver か、その手前の層で行う。
