# ADR 0001: 環境は、同じ AWS アカウントの中で名前で分ける

- 日付: 2026-11-03
- 状態: 採用(dev のみ実装済み。test と prod はこれから作る)

## 状況

dev / test / prod の3つの環境が要る。AWS アカウントは1つで、月額の上限は 10 ドルにしている。

## 決めたこと

- 環境は、アカウントを分けずに、**名前で分ける**。名前は環境名を含める。
  - S3: `ecom-lakehouse-<環境>-<アカウント ID>`
  - IAM ロール: `ecom-<環境>-ingest` / `ecom-<環境>-transform`
  - Athena の workgroup: `ecom-<環境>`
  - Glue のデータベース: `ecom_<環境>_bronze` / `silver` / `gold`
- 環境ごとの定義は1つのモジュール(`terraform/modules/lakehouse_env`)にまとめ、環境名(`env`)を渡して呼び分ける。状態ファイルは環境ごとに分ける(dev は `envs/dev/terraform.tfstate`)。
- アカウント全体で1つしか持てないもの(Budgets、GitHub の OIDC プロバイダ)は、モジュールに入れず `terraform/global` に置く。

## 理由

- 個人の学習用で、アカウントを増やすと、請求、権限、通知の管理が増える。
- 名前に環境を含めれば、リソースの衝突は起きない。
- 定義を1つにまとめれば、直すとき3か所を直さなくて済む。

## 今回のモジュール化で決めたこと

- 既存の dev のリソース 14 件は、`moved` ブロックで住所だけを移し、AWS には触れなかった(置き換え 0、削除 0)。
- `moved.tf` は、dev で apply して `No changes` を確かめたあとに消した。使う人が1人で、apply 済みのため。公式の文書は、共有するモジュールでは残すことを勧めている。
- 実データ入りのバケットは、`prevent_destroy` を付けなかった。定義ごと消えると保護も消えるので、`moved` の書き漏れには効かないため。代わりに、plan を保存し、削除 0 件を確かめてから apply した。

## あきらめたこと(弱い点)

- アカウントを分けたときの、強い境界を持てない。権限の誤りや誤操作が、環境をまたいで効く。信頼ポリシーは全環境で同じ `portfolio-admin` で、分離は名前と権限の範囲だけである。
- 実務では、環境ごとにアカウントを分け、人はスイッチロールで入る。規模が大きくなったら、この形に移す。移すときは、モジュールの `env` を渡す形のまま、provider だけを環境ごとに変えられる。
