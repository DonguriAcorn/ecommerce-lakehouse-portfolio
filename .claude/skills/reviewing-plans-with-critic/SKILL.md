# 計画を plan-critic と3回磨く

## 使う場面
- 使う: フェーズの計画、スコープや順番の変更、データが消える恐れのある作業、ユーザーが慎重に進めたいと言った場面。範囲が分かれるとき(例: フェーズ1と、フェーズ2〜8)は、範囲ごとに3回ずつ行う。
- 使わない: ふだんの設計書(1つの方針書など)。自分で事実を確かめてから、直接見せる。
- 迷ったら、批評を通すかどうかをユーザーに一言聞く。

## 手順
1. 計画をファイル(プランのファイルか docs/ の下書き)に書く。plan-critic は読むだけなので、ファイルのパスを渡す。
2. plan-critic を呼ぶ。毎回、何回目か(全3回)と、前の回で直したことを渡す。
   - 1回目: ルールを守れるか、設計は妥当か、事実が正しいか、抜けはないか。
   - 2回目: 1回目の修正で新たに入った矛盾や、消えたルールがないか。
   - 3回目(最終回): 実行を止める問題と、計画が膨らみすぎていないかに絞る。
3. 指摘を採用するか見送るかを決め、計画を直す。ユーザーが決めるべき点は、次の回の前に、まとめて AskUserQuestion で聞く。細かい仕様は、方針の段階では聞かない(着手するときに聞く)。
4. 承認を求める前に、採用した指摘と見送った指摘を、かんたんな言葉で短く報告する。
